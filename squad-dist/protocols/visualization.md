# Squad 可视化协议 (Visualization Protocol)

> 本文件定义 Squad 智能体调用的强制可视化规则

**版本**: v0.3.0
**状态**: 强制执行 (Mandatory)

---

## ⚠️ 强制协议声明

> **协议违规 = 执行失败**

**BEFORE EVERY agent invocation, MUST display routing decision with 2-part declaration:**

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
▸ SQUAD | 路由决策
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

{emoji} @{agent}:{tag}
   原因: {why this agent was selected}
   预期: {expected outcome}

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**3 个核心要求**:
1. ✅ **Squad 品牌标识** - 始终显示 "SQUAD | 路由决策"
2. ✅ **2 部分声明** - 原因 (Why) + 预期 (Expected)
3. ✅ **智能体 emoji** - 只能使用预设的三个 (🔍/💻/🚦)

---

## 2 部分声明详解

### 部分 1: 原因 (Reason)
**回答**: 为什么选择这个智能体？

**要求**:
- 简洁明了 (1 句话)
- 说明任务特点
- 解释为何适合该智能体

**示例**:
```
✅ Good:
   原因: 需要定位认证模块实现位置
   原因: UI 组件实现，需要前端开发技能
   原因: 验证代码质量和测试覆盖率

❌ Bad:
   原因: 这个任务需要处理  # 太模糊
   原因: 用户要求  # 没有说明为什么选这个智能体
```

### 部分 2: 预期 (Expected)
**回答**: 任务完成后的具体成果是什么？

**要求**:
- 具体可验证
- 描述产出物
- 可量化（如有可能）

**示例**:
```
✅ Good:
   预期: 返回认证模块文件列表和流程概览
   预期: 可交互的主题切换按钮 + 状态持久化
   预期: 所有测试通过 + 覆盖率 >80%

❌ Bad:
   预期: 完成任务  # 太模糊
   预期: 实现功能  # 没有说明具体产出
```

## Emoji 使用规则 (STRICT)

### 允许使用的 Emoji

**只能使用以下 3 个智能体 emoji，NO EXCEPTIONS:**

| Agent | Emoji | 含义 |
|-------|-------|------|
| 研究员 (Researcher) | 🔍 | 搜索、探索、代码分析 |
| 工程师 (Engineer) | 💻 | 编程、实现、代码编写 |
| 测试员 (Tester) | 🚦 | 测试状态、CI/CD、验证 |

### 禁止使用的 Emoji

**❌ 严禁使用以下 emoji:**
- 🎯 (目标) - 已移除
- 🗄️ (文件柜) - 不要用于 backend
- 🎨 (调色板) - 不要用于 frontend
- ⬆️ (箭头) - 不要用于性能提升
- 🔧 (扳手) - 不要用于工程师
- 任何其他装饰性 emoji

**原则**: 风格统一 > 语义丰富

如果需要强调关键词，使用 **粗体** 或 *斜体*，而非添加 emoji。

## 符号系统 (Symbol System)

### 进度状态符号

在智能体执行过程中，使用以下符号表示进度：

| 符号 | 含义 | 颜色 (Squad Theme) | 使用场景 |
|------|------|-------------------|----------|
| ✓ | 完成 (Done) | Terminal Green (#00FF41) | 任务成功完成 |
| ▶ | 进行中 (Running) | Neon Orange (#FF6B35) | 任务正在执行 |
| ○ | 待处理 (Pending) | Gray | 任务排队中 |
| ✗ | 失败 (Failed) | Danger Red (#FF3366) | 任务执行失败 |

### 树状结构符号

用于显示任务步骤和文件结构：

```
├─ 分支继续
└─ 分支结束
```

## Token 效率

**设计目标**: 在保持可视化效果的同时，控制 token 开销

| 组件 | Token 估算 |
|------|-----------|
| Squad 标题行 | ~5 tokens |
| 分隔线 | ~3 tokens |
| Emoji + 智能体声明 | ~8 tokens |
| 2 部分声明 | ~10 tokens |
| 总计 (默认模式) | **~25 tokens** |

**对比**:
- Wukong 4 部分声明: ~100-150 tokens
- Squad 2 部分声明: ~25 tokens
- **效率提升**: 75-80%

## 与 Wukong 的对比

| 特性 | Wukong | Squad |
|------|--------|-------|
| **声明部分** | 4 部分 (分身、原因、技能、预期) | 2 部分 (原因、预期) |
| **Token 开销** | ~100-150 tokens | ~25 tokens |
| **Emoji 数量** | 6 个 (眼耳鼻舌身意) | 3 个 (🔍💻🚦) |
| **品牌标识** | "我将召唤分身" | "SQUAD \| 路由决策" |
| **强制性** | 是 (戒关打回) | 是 (执行失败) |
| **设计理念** | 完整性优先 | Token 效率优先 |

**Squad 优势**:
- ✅ Token 效率高 (减少 75%)
- ✅ 简洁明了
- ✅ 易于理解和遵守
- ✅ 保持专业视觉效果

**Wukong 优势**:
- ✅ 更详细的上下文
- ✅ 技能列表明确
- ✅ 分身概念清晰
